Pursuit: The Climb · Multi-Agent System

Agent Architecture

Our game is played by real people. The AI pieces are facilitator agents — each one runs a part of the experience, shares one game state, and hands control back to a coordinator. This page shows the agents, their roles, and the loop they run.

How the agents work together

One Orchestrator decides which agent is active for the player's current zone. The active agent reads and writes a single Shared Game State (stars, energy, stoplight, zone). The Scorekeeper turns that state into on-screen feedback for the player — closing the loop.

The loop each agent runs

Every facilitator agent runs the same simple cycle — the classic sense → decide → act agent loop — each time the player does something in its zone.

The agents and their roles

Orchestrator Coordinator

Not a character — the controller that sequences the journey and decides which agent is active for the player's current zone, then hands control back when a scene ends.

Senses
current zone, scene-complete signals
Decides
which agent to activate next
Acts
loads the scene, activates one agent

Greeter Reception

Welcomes the player at the star floor and checks them in as a Builder.

Senses
player arrival + check-in choice
Decides
greeting; confirm check-in
Acts
awards the Show Up star

The Platform Facilitator · antagonist-helper

Runs the classroom task — and floods the player with questions ("answer them all"), draining energy until they learn the trick: use AI.

Senses
player answers, time/energy
Decides
which question to pile on next
Acts
poses questions; lowers energy on busywork

AI Helper Lifeline

Triggered by the "Use AI" button. Cuts 100 questions back down to the 3 that matter.

Senses
the "Use AI" request
Decides
the real, essential tasks
Acts
restores energy; awards Do the Work + reveals Hidden Objective #1

Scorekeeper Observer · HUD

Always watching the shared state and turning it into what the player sees — stars, the energy meter, and the stoplight — plus hints and the hidden-block bonus.

Senses
the whole shared game state
Decides
feedback + wayfinding; bonus triggers
Acts
renders HUD; grants surprise rewards
Coordination pattern (for the write-up): this is an orchestrator + shared-state (blackboard) design. A single controller activates one agent at a time, every agent reads/writes one shared state, and a dedicated observer agent (the Scorekeeper) renders that state back to the player. It scales cleanly — later levels add more agents (mentor, interviewer, recruiter, stakeholder) without changing the loop.
